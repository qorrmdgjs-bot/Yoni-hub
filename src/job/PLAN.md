# PLAN.md — 이직 파트너 (Job Search Companion)

> 개인용 이직 관리 웹앱 개발 계획서. 헤드헌터 실무 관점에서 초안을 검토·보강한 버전.

---

## 1. 프로젝트 개요

- **목적**: 경영지원(재무/회계/세무/인사/총무) 6년차 경력직의 이직 활동을 한 곳에서 관리
- **사용자**: 1인, 비개발자 — 한국어 UI, 클릭 위주.
  **이런 도구에 익숙하지 않은 사람이 쓴다. 기능을 더하는 것보다 덜어내는 쪽이 기본값.**
- **사용 환경**: **PC + 모바일 병행** (모바일 사용 비중 높음)
- **핵심 가치**
  1. 여러 채용 플랫폼에 흩어진 지원 현황을 하나의 파이프라인으로
  2. 플랫폼별 프로필 등록 + **현직 노출 차단** 상태를 체크리스트로
  3. 경력기술서/자소서를 투트랙 버전으로 관리
  4. 면접 준비와 회고를 축적
  5. **중복지원·무응답 같은 실무 사고를 사전에 잡아냄**

---

## 2. 초안 대비 보강 사항 (헤드헌터 관점)

| 보강 항목 | 이유 |
|---|---|
| **중복지원 감지** | 서치펌이 A사에 넣은 상태에서 직접 지원이 겹치면 기업 인사팀이 중복 접수로 판단해 **양쪽 다 탈락**시키거나 서치펌과 분쟁이 생긴다. 가장 흔한 자책골 |
| **현직 노출 차단 체크리스트** | 재직 중 이직이므로 사람인·잡코리아 "열람차단 기업" 미설정, 링크드인 프로필 변경 알림 방치가 **현 직장에 이직 사실이 새는 경로**. 계정 생성보다 우선순위가 높다 |
| **파이프라인 9단계 확장** | 초안 7단계에는 인적성/과제, **처우협의**가 없다. 처우협의는 실제 연봉이 결정되는 가장 중요한 구간이고 여기서 며칠씩 머문다 |
| **무응답 추적 + 공고 마감 D-day** | 한국 채용은 불합격 통보 없이 무응답으로 끝나는 비율이 높다. "언제까지 기다릴지" 판단 근거 필요. 마감일은 관심 단계의 핵심 필드인데 초안에 없었다 |
| **연봉 3분할** | 초안은 `salaryRange` 문자열 하나. 현재/희망/제안을 나누지 않으면 처우협의 때 협상 근거가 없다 |
| **DART·크레딧잡 추가** | **재무/회계 직군 지원자가 지원 회사 재무제표를 읽고 면접에 들어가면 거의 확실히 인상을 남긴다.** 이 직군만 쓸 수 있는 무기 |
| **IndexedDB 채택** | localStorage 5MB 초과 시 조용히 저장 실패 → 며칠 뒤에나 발견. 문서 본문 수십 버전이면 현실적 위험 |
| **내보내기/가져오기를 Phase 1로** | 스키마가 바뀔 때마다 실데이터를 옮길 수단이 이미 있어야 한다. 마지막에 붙이면 개발 중 실데이터를 몇 번 날린다 |

## 3. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | `vite` + `@vitejs/plugin-react-swc` | — |
| 스타일 | `tailwindcss` v4 + `@tailwindcss/vite` | CSS-first, 설정 파일 불필요 |
| 상태 | `zustand` + `immer` | React 밖에서 상태 접근 → 자동저장·import가 훅 없이 붙음 |
| 스키마 | `zod` | **타입의 단일 소스**(`z.infer`). 수기 interface는 검증 로직과 반드시 어긋난다 |
| 저장소 | **IndexedDB** (`idb`) | 트랜잭션 원자성 → import 실패 시 기존 데이터 손상 경로가 구조적으로 없음 |
| DnD | `@dnd-kit/*` | `react-beautiful-dnd` 유지보수 중단 |
| 라우팅 | `react-router-dom` `createHashRouter` | 새로고침 시 탭 유지, 정적 배포 404 회피 |
| 날짜 | `date-fns` + `ko` | D-day, ISO 주차, 한국어 포맷 |

**넣지 않는 것**: 차트 라이브러리(Phase 3에서 필요 시), react-hook-form, UI 라이브러리, 백엔드/로그인/크롤링

## 4. 화면 구성 (6개 탭)

> **2026-07-24 개정.** 초안은 7개 탭이었으나 실사용자(비개발자)에게 과하다는 판단으로 줄이고
> **순서를 실제 이직 진행 순서에 맞췄습니다**: `홈 → 기준 → 준비 → 지원 현황 → 면접 → 설정`.
> 메뉴 이름에서 업계 용어(대시보드·파이프라인·CRM)를 걷어냈습니다.
> **준비를 두 번째**에 둔 건 의도입니다 — 재직 중 이직에서 현직 노출 차단이 가장 먼저 해야 할 일인데,
> 뒤쪽 탭에 있으면 마지막에 발견하게 됩니다.

### 4.1 홈 *(구현 완료)*

**숫자가 아니라 할 일을 먼저 보여준다.** "총 지원 12건"을 봐도 다음 행동이 떠오르지 않지만
"내일 면접"은 떠오른다. 그래서 이 순서다:

1. **월 달력** — 지원 현황에 넣은 마감일·면접일·지원일이 그대로 찍힌다.
   지원 건에 날짜를 넣으면 여기에 나온다(별도 일정 입력 없음). 날짜를 누르면 아래에 그 날 일정,
   아무것도 안 고르면 '곧 있을 일'(3주). 모바일은 점, 데스크톱은 회사명.
2. **챙겨야 할 것** — 현직 노출 차단 미완료 / 오래 연락 없는 곳(원클릭 무응답 종료) / 마감 지난 관심 공고 / 백업 오래됨
3. **한눈에** — 진행 중 · 면접 진행 · 처우협의·오퍼 3칸 (누르면 지원 현황으로)

의도적으로 뺀 것: 주간 목표 진행바(압박만 주고 행동이 안 바뀜), 단계별 현황 막대그래프(지원 현황 탭과 중복),
총 지원 건 누적 수, 프로필 업데이트 권장 알림(준비 탭으로 이동).
**통계·그래프는 홈에 올리지 않는다.**

### 4.1-b 기준 — "내가 다니고 싶은 회사" *(구현 완료)*

이직의 기준을 다시 확인하는 화면. **읽기 전용**이다.

- 맨 위에 **한 문장 요약** — 흔들릴 때 이것만 읽으면 된다
- **1. 내적 가치 (성장과 보람)** — ① 더 나은 회사 ② 함께 성장하는 동료 ③ 배울 수 있는 리더 ④ 나 자신의 성장 ⑤ 합당한 보상
- **2. 외적 환경 (근무 만족도)** — ① 문화 ② 근무환경 ③ 위치 ④ 업무
- 맨 아래 **지금 판단이 필요한 곳** — 최종면접·처우협의·오퍼 단계의 지원 건 목록

편집 기능을 넣지 않는 이유: 마음이 흔들릴 때마다 문장을 고칠 수 있으면 기준으로서 기능하지 않는다.
내용은 `data/seed/criteria.ts`에 있고, 수정은 그 파일을 직접 고친다.
맨 아래 목록이 있어야 벽에 붙은 문구로 끝나지 않고 **결정하는 순간에 열어보는 화면**이 된다.

### 4.2 지원 현황 (칸반) — 핵심 *(Phase 1)*

**9단계**: `관심 → 지원완료 → 서류통과 → 인적성/과제 → 1차면접 → 임원/최종면접 → 처우협의 → 오퍼 → 종료`

종료 사유: 합격 / 불합격 / 지원포기 / **무응답 종료** / **오퍼 거절**

- 카드: 회사명, 포지션, 플랫폼, 지원일, 다음 일정, 사용 문서, **D-day 배지**, **무응답 경과 배지**, **중복 배지**
- **단계 이동 2경로** — 데스크톱 DnD + **모든 기기에서 네이티브 `<select>` 상시 노출**. 둘 다 `moveApplication()` 하나만 호출
- 상세 모달: 공고 URL, **공고 원문 붙여넣기**(공고가 내려가면 못 봄), **연봉 3분할**, 연차 필요 여부, 메모, 히스토리 타임라인

**중복지원 감지**: 회사명 정규화(`㈜`/`주식회사`/공백 제거) 후 기존 지원건·헤드헌터 제안 이력과 대조 → 확인 모달. **차단이 아니라 경고**(다른 포지션 중복 지원이 정당한 경우가 있음)

**무응답·마감일**: `lastContactAt` 기준 14일 → 노랑, 30일 → 빨강 + 원클릭 무응답 종료. `deadlineAt` D-3 이하 주황

### 4.3 준비 — 플랫폼 가이드 + 체크리스트 *(Phase 1)*

**지원 채널 6개**

| 플랫폼 | 성격 | 경력직 활용 포인트 |
|---|---|---|
| 리멤버 | 스카웃형 | 명함 기반 경력직 특화. 경력 키워드(결산, 세무신고, 인사노무) 상세 입력이 제안 품질을 좌우 |
| 링크드인 | 스카웃형 | 외국계·대기업 리크루터 채널. 영문 프로필 병행 |
| 원티드 | 지원+추천형 | IT/스타트업. 초기 멤버형 경영지원 포지션에 강점. 합격 보상금 |
| 사람인 | 공고형 | 공고 볼륨 최대. 이력서 공개 시 인재검색 노출 |
| 잡코리아 | 공고형 | 사람인과 병행. 스크랩·맞춤 알림 |
| 잡플래닛 | 리서치형 | 지원 채널 아님. 기업 리뷰·면접 후기 |

**리서치 도구 2개 (추가)**

| 도구 | 용도 |
|---|---|
| 크레딧잡 | 기업 평균연봉·입퇴사자 추이. **처우협의 전 시세 확인** |
| DART 전자공시 | 재무제표·감사보고서. **재무 직군 면접의 최강 차별화 소재** |

**체크리스트 — critical 항목(빨간 강조, 카드 최상단 고정)**

| 플랫폼 | critical |
|---|---|
| 사람인 | 이력서 **열람제한 기업**에 현재 회사 + 계열사 등록 |
| 잡코리아 | 이력서 **열람차단 기업** 설정 |
| 리멤버 | 현재 재직 회사 자동 차단 여부 확인 |
| 링크드인 | Open to Work를 **"리크루터에게만"** / **프로필 변경 알림 OFF** |
| 원티드 | 프로필 공개 범위·특정 기업 차단 |

일반 항목: 계정 생성 / 기본 프로필 등록 / 경력기술서 업로드 / 스카웃 수신 ON / 희망조건 입력 / 프로필 업데이트일 기록(30일 경과 시 배지)

### ~~4.4 문서 관리~~ — **폐기**
경력기술서는 현실적으로 한글/워드로 쓴다. 앱 안에서 긴 본문을 편집하는 화면은 만들지 않는다.
어떤 회사에 어떤 버전을 냈는지는 지원 건 메모로 충분하다.

### ~~4.5 헤드헌터 CRM~~ — **지원 건 안으로 흡수**
헤드헌터 제안은 결국 *회사 하나 + 포지션 하나*라 파이프라인 카드 그 자체다.
별도 탭을 두면 같은 회사를 CRM에 한 번, 지원 건에 또 한 번 입력해야 한다 — 초보자에게 최악의 경험.

→ 지원 건 상세의 **헤드헌터** 영역에 이름·서치펌·연락처·이력서 제출 동의일을 둔다.
지원 경로를 `헤드헌터`로 고르면 `viaSearchFirm`이 자동으로 켜진다(수동 체크에 의존하면
빠뜨렸을 때 중복지원 경고가 조용히 약해진다). 중복지원 감지는 오히려 **더 정확해진다** —
제안이 실제 지원 건으로 기록되기 때문.
포기한 것: 응답성 평가, 회사가 아직 정해지지 않은 단계의 인맥 관리. 1인 이직에는 과한 기능이다.

## 5. 데이터 모델

`src/schema/entities.ts`에 zod로 정의, `z.infer`로 타입 추출. ID는 branded type.

```ts
type Stage =
  | 'interested' | 'applied' | 'doc_passed' | 'assessment'
  | 'interview1' | 'interview_final' | 'negotiation' | 'offer' | 'closed';

type ClosedReason = 'accepted' | 'rejected' | 'withdrawn' | 'ghosted' | 'declined_offer';

interface Application {
  id: ApplicationId;
  company: string;
  companyNormalized: string;   // 중복 감지용
  position: string;
  platform: PlatformId;
  stage: Stage;
  closedReason?: ClosedReason;
  closedNote?: string;

  deadlineAt?: string;         // 공고 마감일 → D-day
  appliedAt?: string;
  lastContactAt?: string;      // 무응답 경과일 기준점
  nextEventAt?: string;
  nextEventNote?: string;
  needsLeave?: boolean;        // 면접에 연차 필요

  salaryCurrent?: string;
  salaryDesired?: string;
  salaryOffered?: string;
  salaryNote?: string;

  documentId?: DocumentId;
  recruiterId?: RecruiterId;
  viaSearchFirm?: boolean;
  resumeConsentAt?: string;
  jobUrl?: string;
  jdText?: string;             // 공고 원문
  memo?: string;
  stageHistory: { stage: Stage; at: string }[];
  createdAt: string; updatedAt: string;
}

interface PlatformStatus {
  platformId: PlatformId;
  checklist: { id: string; item: string; done: boolean; critical?: boolean }[];
  lastProfileUpdate?: string;
  memo?: string;
}
```

`Document` / `Recruiter` / `InterviewPrep` / `InterviewReview` / `Settings`는 초안 유지 + `createdAt`/`updatedAt`.

**저장 규칙**: 모든 엔티티는 `Record<Id, Entity>` 맵. 날짜는 전 계층 ISO 문자열(`Date` 객체를 저장소에 넣지 않음 — JSON 왕복 시 타입이 달라짐).

## 6. 데이터 안전 설계

- **내보내기 봉투**: `{ app: 'job-finder', schemaVersion, exportedAt, data }`
- **가져오기 = preview + commit 분리**
  - `previewImport()` — **완전 순수**. 스토어·IDB 미접근. 파싱/봉투/버전/마이그레이션/검증 단계별 오류 반환
  - `commitImport()` — ① 자동 백업 다운로드 ② 단일 트랜잭션 `replaceAll` ③ 재하이드레이션
  - → **잘못된 JSON이 기존 데이터를 손상시킬 경로가 구조적으로 없음**
- **마이그레이션 체인**: 정수 `SCHEMA_VERSION` + `runMigrations(data, from)`. 로컬 부팅과 import가 같은 함수를 통과. 마이그레이션 함수는 zod 스키마를 import하지 않음(스키마는 항상 최신이라 과거 데이터에 못 씀)
- **저장 실패(quota)**: **아무것도 지우지 않고** 경고 배너 + 원클릭 내보내기(메모리 상태에서 직접 생성 → IDB 없이 동작)
- `navigator.storage.persist()`로 브라우저 자동 삭제 대상에서 제외
- 대시보드 **"마지막 내보내기 후 N일"** 배지 — 브라우저 데이터 삭제가 가장 현실적인 전손 시나리오

## 7. 개발 단계

### Phase 0 — 스캐폴딩
Vite react-ts → Tailwind v4 → tsconfig strict 강화 → `vite.config.ts` cacheDir → AppShell(데스크톱 사이드바 / 모바일 하단 탭바) + 라우트

### Phase 1 — 데이터 기반 + 파이프라인 + 플랫폼
1. `schema/` zod 엔티티 + `SCHEMA_VERSION = 1`
2. `storage/` IndexedDB + 메모리 폴백 + quota
3. `store/` 슬라이스 + hydrate/autosave(600ms 디바운스, 3s maxWait, `pagehide`에 즉시 플러시)
4. `settings/` 내보내기 + 미리보기 있는 가져오기
5. `pipeline/` 9단계 칸반, 중복 감지, 상세 모달
6. `platforms/` 8개 시드 + critical 강조
7. Vercel 정적 배포

### Phase 2 — 단순화 *(완료, 2026-07-24)*
탭 7개 → 5개 · 순서를 이직 진행 순서로 재배치 · 메뉴 이름에서 업계 용어 제거 ·
홈 화면을 "오늘 뭐 하지?"로 재설계 · 헤드헌터를 지원 건 안으로 흡수(`SCHEMA_VERSION` 1→2)

### Phase 3 — 면접 + 내구성
면접 질문은행 + 회고 / 스냅샷 백업 + 복원 / 참조 무결성 검사(cascade 삭제 금지, soft-unlink) / 인쇄 스타일
*(선택: 퍼널 전환율·플랫폼별 성과 분석, 오퍼 비교 테이블 — 단 홈에는 올리지 않는다)*

## 8. UI/UX 원칙

- 한국어 UI, **모바일 우선** 반응형
- 첫 실행 시 플랫폼 카드·기본 면접 질문이 채워진 상태 (빈 화면 금지)
- 상태 색상: 진행 중(파랑) / 면접·마감 임박(주황) / 오퍼(초록) / 종료(회색) / **경고(빨강 — critical 미완료, 중복, 30일 무응답)**
- **한글 IME**: 긴 텍스트는 로컬 state로 받고 `compositionend` 이후에만 스토어 커밋. 조합 중 디바운스 커밋하면 커서가 튀고 글자가 깨진다
- **개인정보**: 데이터는 브라우저에만 저장됨을 설정에 명시. 주민번호·계좌·현직 동료 실명 입력 금지 안내

## 9. 하지 않을 것

- 로그인/회원가입, 서버/DB
- 채용 사이트 API 연동·크롤링 (약관 이슈 — 공고 원문은 수동 붙여넣기)
- PC↔폰 자동 동기화 (브라우저 저장의 근본 한계. JSON 수동 이동으로 대응)

## 10. 개발 환경 주의 — OneDrive

프로젝트가 OneDrive 동기화 폴더 안에 있어 `node_modules` 잠금·placeholder 문제가 발생할 수 있다.

1. `vite.config.ts`에서 `cacheDir`를 OneDrive 밖으로 지정 (적용됨)
2. OneDrive 설정에서 `node_modules`·`dist` 동기화 제외
3. 설치 실패 시 OneDrive 동기화 2시간 일시중지 후 재시도
4. **가장 확실한 해법**: 프로젝트를 `C:\dev\job_finder`로 이동 (경로의 한글·공백 문제도 함께 해소)
